My inventory application uses classes, objects, attributes, and methods to organize product information. The Product class serves as a blueprint that defines what each product stores and what it can do. Its three private attributes are name, price, and quantity. Keeping these fields private demonstrates encapsulation because InventoryApp accesses them through public getter methods rather than changing them directly. The constructor initializes these attributes whenever a new Product object is created. InventoryApp creates two separate objects: an adjustable dumbbell and a jump rope. Each object has its own values, even though both follow the same class structure. The calculateInventoryValue method multiplies an object's price by its quantity and returns the result. InventoryApp combines those results to calculate the total inventory value. Finally, a formatting method prepares product details for console output and a JOptionPane dialog, showing how multiple classes and methods cooperate to complete a task within one Java program.
